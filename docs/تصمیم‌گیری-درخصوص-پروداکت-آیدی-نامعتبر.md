
# بررسی مشکل Foreign Key در ارتباط Sales و Products

## 1. توضیح Foreign Key و Nullable بودن

یک ستون Nullable می‌تواند Foreign Key باشد.

Foreign Key به این معنی نیست که ستون حتماً باید مقدار داشته باشد؛ بلکه یعنی:

> اگر مقداری وجود داشت، آن مقدار باید در جدول مرجع وجود داشته باشد.

مثال:

جدول Products:

| product_id |
| ---------- |
| P001       |
| P002       |

جدول Sales:

| sale_id | product_id |
| ------- | ---------- |
| 1       | P001       |
| 2       | NULL       |

این حالت معتبر است.

رکورد دوم محصول ندارد، اما چون مقداری ثبت نشده، نقض Foreign Key نیست.

اما:

| sale_id | product_id |
| ------- | ---------- |
| 3       | P999       |

نامعتبر است، چون P999 در جدول Products وجود ندارد.

---

# گزارش مشکل کیفیت داده

## مشکل مشاهده‌شده

در جدول `sales` مقادیری برای `product_id` وجود دارند که در جدول مرجع `products` تعریف نشده‌اند.

وضعیت فعلی:

### جدول Products

```
P001 تا P015
```

### جدول Sales

شامل مقادیری مانند:

```
P001
P002
P999
```

است.

مقدار:

```
P999
```

در جدول Products وجود ندارد.

---

## Query بررسی مشکل

برای پیدا کردن Product IDهایی که در Sales وجود دارند ولی در Products تعریف نشده‌اند:

```sql
SELECT DISTINCT product_id
FROM sales
WHERE product_id NOT IN (
    SELECT product_id
    FROM products
);
```

نتیجه تحلیل:

```
P999
```

است.

نتیجه:

> تعدادی از رکوردهای فروش به محصولی اشاره می‌کنند که در Master Data محصولات وجود ندارد.

این یک مشکل Data Quality است، نه مشکل طراحی داشبورد.

# اثر این مشکل در Power BI

## حالت اول: بدون Foreign Key

Power BI همچنان می‌تواند Relationship بسازد.

اما داده‌های نامعتبر باعث ناقص شدن تحلیل‌ها می‌شوند.

مثال:

کل فروش:

```
100 میلیارد تومان
```

اما وقتی بر اساس محصول تحلیل کنیم:

```
95 میلیارد تومان
```

علت:

فروش مربوط به P999 وجود دارد، اما محصولی برای اتصال به آن وجود ندارد.

در نتیجه:

* KPI کلی فروش درست است.
* تحلیل محصول، دسته‌بندی و سود محصول ناقص می‌شود.

---

## حالت دوم: ایجاد Foreign Key با داده فعلی

Migration شکست می‌خورد.

چون دیتابیس اجازه نمی‌دهد:

```
sales.product_id = P999
```

وجود داشته باشد وقتی:

```
products.product_id = P999
```

وجود ندارد.

# تصمیم‌های ممکن

## گزینه ۱ — ساخت Unknown Product و اصلاح Mapping

روش:

یک محصول خاص در جدول Products ایجاد شود:

```
product_id = UNKNOWN
name = محصول نامشخص
```

سپس:

```
P999 → UNKNOWN
```

شود.

### مزایا

* هیچ فروش واقعی حذف نمی‌شود.
* Revenue کلی دقیق باقی می‌ماند.
* می‌توان مقدار فروش بدون Mapping را اندازه‌گیری کرد.
* امکان استفاده از Foreign Key فراهم می‌شود.

### معایب

* نیاز به اصلاح داده دارد.
* باید تعداد فروش‌های Unknown مانیتور شود.

---

## گزینه ۲ — حذف Foreign Key و کنترل در Power BI

در این حالت Relationship فقط در Power BI ساخته می‌شود.

### مزایا

* نیاز به تغییر داده فعلی ندارد.
* سریع‌ترین راه است.

### معایب

* دیتابیس جلوی ورود داده خراب را نمی‌گیرد.
* مشکلات Data Quality ممکن است در آینده بیشتر شود.
* احتمال اختلاف بین KPIهای کلی و تحلیل‌های جزئی وجود دارد.

---

## گزینه ۳ — حذف فروش‌هایی که Product معتبر ندارند

### مزایا

### معایب

* برای داشبورد مدیریتی تصمیم خطرناکی است.

یعنی اصلاح Pipeline پاکسازی و Load دوباره داده‌ها.

### مزایا

* ساختار داده نهایی تمیزتر می‌شود.
* مشکلات ریشه‌ای حل می‌شوند.

### معایب

* هزینه زمانی بیشتر دارد.
* نیاز به اجرای دوباره Cleaning و Loading دارد.
